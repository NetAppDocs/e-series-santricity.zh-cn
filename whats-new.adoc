= SANtricity OS 12.10 中的新增功能
:allow-uri-read: 
:experimental:

:imagesdir: ./media/


[role="lead"]
下表介绍了 SANtricity System Manager 12.10 中的新功能。



[[new-features-in-version-12-10]]
== 版本 12.10 中的新增功能

[cols="35h,~"]
|===
| 新增功能 | Description 


 a| 
EF50 和 EF80 存储系统的 SAS 扩展支持
 a| 
EF50 和 EF80 存储系统现在支持 SAS 扩展，从而提高了存储容量和灵活性。借助 SAS 扩展，您可以将其他存储盘柜连接到 EF50 和 EF80 系统，从而根据需要扩展存储环境。此功能对于需要高容量存储解决方案并希望在 EF50 和 EF80 平台上实现投资最大化的组织尤其有益。



 a| 
对 E 系列存储系统的 NVMe over TCP 支持
 a| 
E 系列存储系统现在支持 NVMe over TCP，为高性能存储访问提供额外的主机接口选项。NVMe over TCP 允许在存储系统和连接的主机之间进行高效、低延迟的通信，充分利用 NVMe 协议在标准 TCP/IP 网络上的优势。这一支持增强了 E 系列系统的多功能性，使组织能够在首选或需要 NVMe over TCP 的环境中部署这些系统。



 a| 
SANtricity System Manager 的用户界面增强功能
 a| 
SANtricity System Manager 用户界面获得了额外的增强功能，以提高导航、可用性和整体用户体验。这些增强功能包括更新的管理任务布局和组织，以及用于常见存储管理操作的更直观的工作流程。



 a| 
扩展的 E 系列平台支持新的 SANtricity System Manager 用户界面
 a| 
SANtricity System Manager 的新用户界面在针对 EF80 和 EF50 存储系统的 SANtricity 12.00 版本中引入，现已扩展以支持其他 E-Series 存储平台。这意味着管理更广泛的 E-Series 存储系统的用户现在可以从现代化的界面和增强的可用性功能中受益。扩展的支持包括与特定型号的 E-Series 存储系统的兼容性，使用户能够在更多存储基础架构中利用改进的导航功能和简化的管理任务。



 a| 
EF80 和 EF50 系统的混合性能和容量驱动器支持
 a| 
EF80 和 EF50 存储系统现在支持在同一存储阵列中使用性能型和容量型 NVMe SSD 驱动器，但须满足最低驱动器数量要求（性能型为 6 个，容量型为 12 个）。性能型和容量型驱动器必须分别保存在各自的池和卷组中。



 a| 
增加了标准卷名和精简卷名的字符限制
 a| 
标准和精简卷名的字符限制已从 30 个字符增加到 60 个字符。


NOTE: 如果存在名称长于 30 个字符的标准卷或精简卷，则不支持降级到 SANtricity 操作系统软件版本 11.90 或更早版本。如果您计划降级到 SANtricity 操作系统软件版本 11.90 或更早版本，请在降级前更改名称长于 30 个字符的任何标准卷或精简卷的名称。



 a| 
SANtricity System Manager 用户界面的最小非活动超时限制现在为 10 分钟
 a| 
SANtricity System Manager 用户界面的非活动超时限制已更新为至少 10 分钟。此前，非活动超时的最小限制为 15 分钟。此更改通过确保用户界面在 10 分钟不活动后自动注销，有助于增强安全性。

|===


[[new-features-in-version-12-0r1]]
== 版本 12.0R1 中的新增功能

此版本仅包含小的更改，没有新功能。有关此版本中更改的更多信息，请参见 E-Series SANtricity 操作系统 12.0R1 README。



[[new-features-in-version-12-0]]
== 版本 12.0 中的新增功能


NOTE: SANtricity OS 12.0 版本仅与新的 EF80 和 EF50 全闪存存储系统兼容。如果使用的是 SANtricity OS 11.9 或更早版本，请参阅 link:known-issues.html["已知问题"] 以获取以前版本中的新功能列表。

[cols="35h,~"]
|===
| 新增功能 | Description 


 a| 
新存储系统型号 – EF80 和 EF50 全闪存存储系统
 a| 
此版本引入了 EF80 和 EF50 全 NVMe 闪存存储系统。EF80 和 EF50 支持 24 个 NVME SSD 驱动器和每个控制器一个控制器间镜像卡。支持的 NVMe over Fabrics 主机接口包括 NVMe over RoCE、NVMe over IB、EF80 的 NVMe over FC 和 EF50 的 NVMe over FC。支持的 SCSI 接口是两个系统的光纤通道。EF50 支持每个控制器最多两个主机接口卡，而 EF80 支持每个控制器最多三个主机接口卡。

EF80 和 EF50 也支持 30TB 或 60TB 大小的大容量 NVMe SSD 驱动器。EF80 和 EF50 只能在阵列装有 30TB 或 60TB 驱动器时使用动态磁盘池。



 a| 
SANtricity System Manager 的新用户界面
 a| 
对于新的 EF80 和 EF50 控制器，SANtricity System Manager 用户界面经过重新设计，以提供更现代的外观和感觉。新界面包括左侧面板导航和增强的可用性，以简化管理任务。


NOTE: 新的用户界面目前仅适用于带有 SANtricity 12.00 版本的 EF80 和 EF50 存储系统。如果使用的是 SANtricity 11.9 或更早版本，请参阅 link:https://docs.netapp.com/us-en/e-series-santricity-119/system-manager/index.html["SANtricity系统管理器11.9."] 使用旧版用户界面的说明。



 a| 
服务器证书的使用者备用名称 (SAN) 现在仅允许字母、数字和连字符
 a| 
在 SANtricity System Manager 或 Unified Manager 中创建或编辑服务器证书时，使用者备用名称 (SAN) 字段现在只允许使用字母、数字和连字符。此更改可增强安全性，并确保与 SSL/TLS 证书的行业标准兼容。



 a| 
对于基于 SSD 和 NVMe 的系统，动态磁盘池段大小现在默认为 32K
 a| 
对于基于 SSD 和 NVMe 的系统上的动态磁盘池，默认数据段大小已更改为 32K。以前，这些系统的动态磁盘池默认段大小固定为 128K。此更改可优化涉及小型和大型 I/O 操作混合的工作负载的性能。



 a| 
现在可在 SANtricity System Manager 中使用脚本编辑器
 a| 
SANtricity System Manager 中现在提供了新的脚本编辑器。脚本编辑器允许您创建或编辑脚本文件，将脚本文件保存到存储管理站的本地磁盘，或从磁盘加载脚本文件。脚本编辑器提供用于管理存储系统的语法检查和命令执行功能。有关详细信息，请参见link:sm-support/use-script-editor.html["使用脚本编辑器"^]。

|===
